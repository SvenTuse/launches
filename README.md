# Research Lounge

Приватная библиотека case study. Next.js 16 / React 19 / TypeScript.

## Запуск на компьютере

Требуется Node.js 22 или новее. На текущем компьютере Node.js и зависимости уже установлены, а `.env.local` настроен.

Откройте папку проекта в Проводнике, нажмите правой кнопкой по пустому месту и выберите «Открыть в терминале». Запустите:

```powershell
npm.cmd run dev
```

Дождитесь сообщения `Ready`, затем откройте http://localhost:3000. Оставляйте терминал открытым, пока пользуетесь сайтом. Для остановки нажмите `Ctrl+C`. Если порт 3000 занят уже работающим сайтом, просто откройте его; если Next.js выбрал другой порт, используйте адрес из терминала.

При первом запуске новой копии проекта сначала установите зависимости:

```sh
npm ci
npm run dev
```

Для запуска production-версии локально используйте `npm.cmd run build`, затем `npm.cmd start`.

Откройте http://localhost:3000. Логин — `admin`. Сгенерированный пароль и ключ сессии находятся в `.env.local`. Файл не включается в Git или загрузку через Vercel CLI. Для новой копии проекта скопируйте `.env.example` в `.env.local` и задайте свои случайные значения.

При `STORAGE_DRIVER=local` редактор меняет исходные файлы в `case-study projects` и `how we do it`. Предыдущие версии отредактированных файлов сохраняются в `.local-history` с датой и уникальным идентификатором. Загрузки попадают в выбранную папку проекта. Существующие файлы не перезаписываются загрузкой.

## Что доступно

- Интерфейс полностью на английском; исходные тексты исследований отображаются на языке файлов.
- Все case study обнаруживаются по папкам, без ручного списка.
- Карточки, фильтры, поиск по названиям проектов и файлов, избранное в текущем браузере.
- Данные и внешние ссылки из `project-info.json` / `Project Info.json`. Если JSON отсутствует, сведения извлекаются из начала `project-overview.md`.
- Markdown с таблицами, оглавлением, ссылками на соседние файлы и скриншоты; JSON с форматированием.
- Редактирование MD, TXT, JSON и CSV, создание Markdown-заметок. `Ctrl/Cmd+S` сохраняет изменения.
- Защита от сохранения устаревшей версии при параллельном редактировании.
- Загрузка нескольких файлов, выбор существующей или новой вложенной папки, drag-and-drop. Максимум **4 МБ на один файл**, чтобы запрос укладывался в ограничение Vercel Functions. Существующие исходные файлы большего размера доступны для просмотра.
- Галерея изображений, лента миниатюр, увеличение, клавиши ←/→ и Esc. Аудио и видео открываются со стандартными элементами управления; видео поддерживает Range-запросы.
- Все файлы выдаются через проверку авторизации, включая изображения. HTML из Markdown не исполняется. Внешние изображения из Markdown автоматически не загружаются.

## Деплой на Vercel

1. Поместите проект в **приватный** Git-репозиторий и импортируйте его в Vercel. Либо выполните `npx vercel` из корня проекта. Исходные case study должны входить в загружаемый проект; они не находятся в `public` и не выдаются без авторизации.
2. Framework Preset: **Next.js**. Root Directory: корень проекта. Build Command: `npm run build`. Node.js: **22.x**. Install Command: `npm ci`.
3. В Vercel → Project → Settings → Environment Variables добавьте значения из `.env.local`:
   - `ADMIN_USERNAME=admin`
   - `ADMIN_PASSWORD` — сгенерированный пароль.
   - `SESSION_SECRET` — сгенерированный ключ длиной не менее 32 символов.
   - `STORAGE_DRIVER=blob`
4. В Project → Storage создайте **Private Blob store** и подключите его к проекту. Vercel автоматически предоставляет `BLOB_STORE_ID` и OIDC-доступ подключённым окружениям; вручную добавлять `BLOB_READ_WRITE_TOKEN` для деплоя на Vercel не нужно. Публичное Blob-хранилище для этого приложения не подходит.
5. Выполните Deploy / Redeploy после настройки переменных. Если к одному хранилищу подключены Production и Preview, изменения из обоих окружений будут общими; для изоляции подключите отдельное приватное хранилище к Preview.
6. Откройте сайт, войдите как `admin`, создайте заметку и обновите страницу. Повторите проверку после Redeploy: заметка должна остаться.

### Как сохраняются данные на Vercel

Файловая система serverless-функций не подходит для постоянных изменений. Исходные материалы входят в закрытый серверный пакет. Новые файлы и отредактированные версии сохраняются в **Private Vercel Blob** под префиксом `kai-library/` и при чтении имеют приоритет над исходными файлами. Поэтому изменения переживают перезапуск и повторный деплой, пока используется то же хранилище и те же имена папок проектов.

В рабочую папку на компьютере облачные изменения автоматически не копируются. Их можно скачать из интерфейса. Переименование исходной папки проекта меняет его идентификатор — перед переименованием сохраните связанные изменения из Blob. Локальная `.local-history` относится к локальному режиму; в Blob хранится актуальная версия каждого файла, без истории откатов.

На Vercel приложение автоматически использует Blob, даже если по ошибке указано `STORAGE_DRIVER=local`. При отсутствии подключения Blob или учётных данных доступен просмотр исходных материалов, а сохранение отключено с объяснением в интерфейсе. Ошибка подключения хранилища не маскируется возвратом к потенциально устаревшим исходным данным.

### Доступ

Сессия действует 12 часов и хранится в подписанной HttpOnly / SameSite=Strict cookie; в production — Secure. Пароль и секрет не отправляются в клиентский код. Все операции изменения проверяют Origin. Локальный ограничитель входа допускает 10 попыток за 15 минут на IP в одном процессе. Для общего ограничения попыток между serverless-инстансами настройте Vercel Firewall для `POST /api/auth` — встроенный счётчик не распределённый. Чтобы отозвать все сессии, измените `SESSION_SECRET` и выполните Redeploy.

## Проверки

```sh
npm run typecheck
npm test
npm run build
```

Проверка API при работающем локальном сервере:

```sh
node scripts/smoke.mjs
```

Она использует `.env.local`, создаёт временный тестовый проект и удаляет только свои тестовые файлы. Проверяет авторизацию, защиту путей и межсайтовых запросов, создание/сохранение, конфликты, JSON, загрузку и Range-запросы медиа. Запускать только с локальным хранилищем.

Облачную запись через OIDC нужно проверить после подключения Private Blob к собственному Vercel-проекту.

Документация: [Vercel Private Blob](https://vercel.com/docs/vercel-blob/private-storage), [Blob SDK](https://vercel.com/docs/vercel-blob/using-blob-sdk), [Vercel Functions limits](https://vercel.com/docs/functions/limitations).
